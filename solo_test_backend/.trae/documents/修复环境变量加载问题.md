## 问题分析

在NestJS应用中，装饰器内的表达式（如`process.env.MONGODB_URI`）会在模块加载时立即求值，而`dotenv.config()`的执行时机晚于`AppModule`的加载，导致`process.env.MONGODB_URI`为`undefined`。

## 解决方案

使用NestJS推荐的环境变量管理方式，结合`@nestjs/config`模块的`ConfigService`和异步配置。

## 修复步骤

### 步骤1：修改app.module.ts，使用异步配置

```typescript
// 将直接使用process.env改为使用ConfigService
MongooseModule.forRootAsync({
  imports: [ConfigModule],
  useFactory: (configService: ConfigService) => ({
    uri: configService.get<string>('MONGODB_URI'),
  }),
  inject: [ConfigService],
})
```

### 步骤2：确保main.ts中的dotenv.config()调用顺序正确

```typescript
// 推荐将dotenv.config()放在一个单独的文件中
// 创建env.ts文件：
// import * as dotenv from 'dotenv';
// dotenv.config();

// 然后在main.ts中首先导入：
import './env';
import { NestFactory } from '@nestjs/core';
// 其他导入...
```

### 步骤3：验证修复效果

1. 重新构建项目：`npm run build`
2. 在服务器上测试：`node main.js`
3. 检查编译后的代码，确认MongoDB连接字符串不再硬编码

### 步骤4：优化环境变量管理（可选）

1. 使用`ConfigService`替代所有直接访问`process.env`的地方
2. 为环境变量添加类型定义
3. 实现环境变量验证

## 预期效果

修复后，应用启动时会先加载环境变量，然后再初始化MongoDB连接，解决`process.env.MONGODB_URI`无法找到的问题。

## 注意事项

* 确保服务器上的`.env`文件位于应用根目录

* 确保`.env`文件中的`MONGODB_URI`配置正确

* 推荐使用PM2管理Node.js进程，确保应用稳定运行
